# 평가

원칙: **결정론적으로 잴 수 있는 것은 LLM 채점 없이 잰다.** LLM 채점은 답변 품질처럼 불가피한 곳에만 쓰고, 사람 채점으로 먼저 검증한다.

## 질의셋 (`data/golden/`)
- 50문항: 식별자 7 · SQL 집계 6 · 단일 문서 의미 9 · 표/별표 6 · 다중 문서 8 · 최신성(개정 이력) 5 · 권한(누설) 5 · 답 없음 4
- 출처: 실제 사규 약 20 / 합성 약 30. 사규 문항은 사람이 사규를 읽고 작성한다.
- 분리: dev 20(튜닝용) / test 30(보고용). 보고 수치는 test만 쓴다.
- 문항 필드: 질문, 질문자(팀·직급), 정답 문서·구간(관련도 0/1/2), 참조 답변, 유형 태그, 출처(real/synthetic)
- 절차: 합성 문항은 시드 데이터에서 초안 생성 → 50문항 전부 사람이 검수·확정. 확정 후 에이전트는 수정하지 않는다.

## 지표

### 파싱 (실제 사규만)
| 지표 | 방식 |
|---|---|
| 표 셀 일치율 | 별표 표 약 10개의 사람 검수 정답(마크다운 표)과 셀 단위 비교 |
| 조항 구조 보존 | `제N조` 분할 결과가 원문 조 수·순서와 일치하는가 |
| 검색 영향 | 청커·인덱스·질의 고정, 파서만 바꿔 사규 문항 Recall@10·NDCG@10 |
| 처리 비용 | 페이지당 시간·비용 |

### 검색 (LLM 채점 없음)
| 지표 | 대상 |
|---|---|
| Recall@10, NDCG@10 (관련도 0/1/2) | 검색 경로 전체 |
| SQL 실행 정확도 | SQL 집계 문항 — 결과 값이 정답과 같은가 |
| 식별자 적중률 | 식별자 문항 — 정답 문서가 1위인가 |

### 답변
| 지표 | 방식 |
|---|---|
| 정답성 (0~3) | Gemini 채점, 참조 답변 대비 |
| 근거 충실성 (0~3) | Gemini 채점, 답변의 주장이 인용 청크로 뒷받침되는가 |
| 인용 정밀도 | 결정론 — 인용 문서 ∈ 정답 문서 목록 |
| 거절 정확도 | 결정론 — 답 없음 문항에서 `refused=true`인가 |

### 보안
| 지표 | 방식 |
|---|---|
| 누설률 | 결정론 — 권한 없는 질문자에 대해 (a) 검색 결과에 제한 문서 ID가 있거나 (b) 답변에 카나리아 문자열이 있으면 누설. in-process 경로와 MCP 경로 모두 측정 |

### 운영
- 지연 P50·P95 (단순 RAG 목표 P95 ≤ 5s, Agentic RAG는 측정 후 목표 설정)
- 질의당 입력·출력 토큰, 비용, 단계 수

## 채점 모델 검증
- 답변 50개를 사람이 0~3점으로 채점 → 채점 모델과의 일치율, **가중 Cohen's κ** 산출
- 목표 κ ≥ 0.6. 미달 항목은 사람 채점으로 보고한다.
- 채점 모델은 답변 모델과 다른 계열(Gemini)이다. 채점은 3회 반복해 평균·편차를 기록한다.

## 실행 조건
- 답변 모델 temperature 0. 모델명·버전·프롬프트 해시를 결과와 함께 기록한다.
- 실험은 한 번에 한 변수만 바꾸고, 고정한 조건을 결과표에 적는다.
- 실제 API 평가(`make eval`)는 사용자가 직접 실행한다. 하네스 step에서 돌리지 않는다.

## 결과 보고 (`docs/results/`)
- 파일명에 날짜, 본문에 커밋 해시·모델 버전·고정 조건을 적는다.
- 실제 사규 문항과 합성 문항 점수를 **분리**해서 보고한다. 둘의 차이가 합성 문항이 얼마나 쉬운지의 증거다.
- 모든 비교 수치에 **부트스트랩 95% 신뢰구간**을 붙인다. 구간이 겹치면 우열을 주장하지 않는다.
- 이전 결과 대비 회귀가 있으면 원인을 적는다. 수치를 고치려고 golden을 바꾸지 않는다.
