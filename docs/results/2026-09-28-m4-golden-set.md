## 사람 검수 절차

- 검수 패킷의 Claude 판단은 기본값으로 수락하며, 사람은 동의하지 않는 항목만 수정 사유와 값을 적는다.
- 확정 순서: `make golden-promote`(split을 다시 계산해 `data/manifest/golden_review.json`에 기록) → 그 파일의 H7 값(`split.gold.h7`의 합성 n·실제 n)을 `docs/results/hypotheses.md` H7 판정 문항 수에 고정 → 그다음에야 M5 결과를 본다. 고정 뒤에는 바꾸지 않는다(ADR-026).
- 각 행은 사람이 `reviewer`와 `reviewed_on`으로 서명해 확정한다. 도구는 두 필드를 미리 채우지 않는다.
- 선택 기능으로 점검용 더미 문항 3개를 섞고 적발 수를 보고한다. 더미 문항은 골드 파일·qrels·split에 넣지 않는다.
- **더미 설계 경과**: 처음에는 더미의 Claude 판정 항목 하나를 일부러 뒤집는 방식이었다. 그런데 일반 문항의 판정이 전부 Y(1,1,1)가 되면서, 판정 값에 0이 하나라도 있는 행이 곧 더미로 식별돼 점검이 무의미해졌다. 그래서 더미도 원본과 같은 Claude 판정(1,1,1, 원본 메모 그대로)을 쓰고, 대신 패킷에 렌더링할 때만 문항 내용에 결함을 하나 심는 방식으로 바꿨다: q1형(질문에서 앵커 값 하나를 빼 모호하게 함), q2형(정답 구간에서 관련도 2 문서 하나를 뺌), q3형(기대 응답을 틀리게 표시). 결함은 렌더링에만 적용되고 실제 문항 레코드는 손대지 않는다.
- **더미 결과(적발 1/3)**: q2형(근거 문서 하나를 뺀 문항)은 적발됐다. q1형(앵커 값 하나를 뺀 문항)은 놓쳤다. q3형(기대 응답을 틀리게 표시한 문항)은 검수자가 쓴 보조 검수 카드에 기대 응답 칸이 없어 측정할 수 없었다.

## 한계

- 합성 문항은 실제 문항보다 쉽다.
- `temporal:as_of_event`는 골드 대응 문항이 없어 실버 결과로 골드의 방향을 확인할 수 없다.
- Claude 판단을 기본값으로 수락하는 검수 방식에는 확인 편향 위험이 있다.
- 실제 규정 문항의 초안을 Claude가 작성하므로 초안이 사람 판단을 끌어갈 수 있다. 최종 확정은 사람이 전부 수행한다.
- 최신성(`temporal:revision`) 5문항은 개정 후 현행 버전이 정답이다. M5 인덱스에 해당 5개 규정의 개정 전 버전이 들어 있어야 최신성 판별이 실제로 시험된다(M5 선행 조건). 5문항 중 3문항은 질문에 개정일이 없고 2문항은 날짜 명시형이다.
- multi_doc은 연결형(사건→그 사건의 서비스→서비스 사실)과 비교형(사건 ID 2개의 같은 속성)만 있다. 같은 사건의 사실은 전부 한 문서에 함께 있어 같은 사건형 후보가 0이고, 다양성 상한 때문에 실버 multi_doc은 35에서 23으로 줄었으며 다른 유형으로 재배분하지 않았다(실버 138문항).
- 비교형이 두 사건을 묶어 실버 관련 문서 그룹이 커졌고(최대 90문항), 할당을 맞추려고 그룹을 나눈 결과 실버 dev↔test 누수 문서가 36개다. 실버는 방향 확인용이라 수용한다. 골드는 누수 0이다.
- 표 문항 g-real-007은 확정 표에 금액 단위가 없다(M2 표 추출에서 단위·캡션이 누락됐을 수 있음). 검수에서 원문으로 단위를 확인한다.
- 권한 문항 질문 문장이 골드·실버 각 1건씩 두 쌍 중복된다("billing-api의 제한 문서 확인 코드는 무엇인가요?", "people-portal의 제한 문서 확인 코드는 무엇인가요?"). 질문자와 대상 제한 문서는 서로 달라 평가상 오류는 아니지만, 검수자에게는 같은 질문이 두 번 보인다. 문항을 교체하지 않고 수용했다.
- 합성 코퍼스의 서술형 사실 표현이 반복된다. 2개 이상 문서에 나오는 서술형 사실 160개 중 108개(68%)가 공백·마침표 차이를 빼면 문서마다 동일한 문장이다. 사실을 표시(`<fact id="...">…</fact>`)로 감싸 그대로 옮겨 쓰게 한 생성 설계 때문이다. BM25 같은 어휘 일치 방식에 유리하게 작용할 수 있어, M5에서 H2(hybrid > BM25)를 출처별(실제/합성)·반복 여부별로 나눠 보고한다. 차이가 크면 코퍼스 v2(서술형 사실마다 표현 변형 2~3개를 두고, 검증기는 그중 하나와 일치하면 통과시키는 방식)를 검토한다.
- LLM 호출을 Batch에서 동기 호출 기본으로 바꿨다(ADR-027). M4 질의 초안 비용은 Batch $0.08 + 동기 재작성 약 $0.06이다.
