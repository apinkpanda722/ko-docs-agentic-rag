## 목적과 범위

M5 검색 구성을 유지한 단순 RAG·Agentic RAG의 결정론 답변 지표·운영 지표와 MCP 도구 계약을 보고한다. H5는 이 phase에서 판정하지 않으며 M7의 Gemini 채점 몫이다. H5 상태는 채점 대기(M7)다.

## 고정 조건

- M5 최종 구성: nori, hybrid_weighted, bm25_weight 0.7, candidate_chunks 50, 구조 청킹 인덱스 `kodocs-m5-composite-structural`. config_hash는 `455f063edd2654326d62607d78bc6f0079a25f30d77b29c274ca345ba9ed4a7d`로 고정한다. M5 결과와 산출물을 재계산하지 않는다.
- [ADR-029](../ADR.md#adr-029-m6-에이전트도구-계약mcp-서버-설계): 단순 RAG는 검색 1회, 두 시스템은 같은 최종 답변 프롬프트·구조화 출력·모델·effort를 사용한다. 두 시스템 모두 `prefer_current`를 켠다.
- 검색 반환 top-k 8청크, 텍스트 6,000자. 각 도구의 직렬화 결과도 6,000자 이내다. lookup은 최대 5문서·문서당 1,200자, 문서 조회는 본문 6,000자·truncated, SQL은 뒤 행부터 제외·truncated다. Agentic 최종 근거는 라운드로빈 배분으로 합계 6,000자 이내다.
- 가드레일: 도구 호출 총 MAX_STEPS=5(병렬도 각각 계산), 문항당 토큰 상한 100,000, 요청별 타임아웃 30초, 전체 타임아웃 단순 45초·Agentic 120초, 호출별 max_output_tokens 4,000. 입력 상한 272,000토큰, 도구 인자 길이 query 500자·SQL 2,000자·식별자/문서/섹션 키 100자.
- 답변 모델 ID 후보: `gpt-6-luna`, `gpt-6.1-sol`. Responses API, reasoning.effort=low, temperature·top_p는 전송하지 않고 null 기록. 두 후보 사이에서 바뀌는 변수는 모델 ID 하나다. 선택 모델을 두 시스템에 동일하게 사용한다. 모델 설정 해시·프롬프트 해시·가드레일 해시는 생성 영역에서 기록한다.
- dev 비교는 2모델 × 2시스템 × 75문항=300회, 정답 값 포함률 분모는 값이 있는 56문항(실제 3·합성 53). test는 골드 30문항 × 두 시스템에 H5 방향 확인 보조용 실버 83문항 × 두 시스템을 한 실행 단위·한 잠금으로 더해, 시스템·문항당 1회다. 동시성 기본 4, P95 판정은 M7에서 동시성 1 별도 실행으로 한다.

## 사용자 실행 절차

1. `make up` 후 M5 인덱스 4개(`kodocs-m5-composite-fixed`, `kodocs-m5-composite-structural`, `kodocs-m5-pypdf-structural`, `kodocs-m5-upstage-structural`)가 있는지 확인한다. M5 확정 산출물을 덮어쓰지 않는다.
2. `make m6-inputs`로 입력 집계를 만든다.
3. `make m6-tokens`로 데모 인증을 준비한다. 평문은 gitignore된 파일에만 보관한다.
4. `make m6-temporal`로 현행 우선 전후 순위를 수집한다.
5. `make test-integration` 결과를 위 측정 환경 칸에 기록한다.
6. `make m6-dry` 후 예상 비용과 월 상한을 확인한다.
7. 선택적으로 `LIMIT=5 make m6-dev` 파일럿을 실행한 뒤 `make m6-dev`로 전체 비교를 한다. 파일럿은 모델 선택에 쓰지 않는다.
8. `make m6-freeze`로 모델·프롬프트·가드레일을 고정한다.
9. `make m6-test` 후 `make m6-report`를 실행한다. 재실행은 `RERUN_REASON="사유" make m6-test` 후 `make m6-report`이며, 이전 결과를 지우지 않는다.
10. **OpenAI 콘솔 Usage를 실제 실행 전후로 기록해 원장과 대조한다(FP-037).** 원장만으로 청구 검증 완료를 선언하지 않는다.
11. **결과 산출물·문서를 커밋하기 전에 `make verify` 통과를 확인한다.** M5 결과 PR에서 검증과 커밋 순서가 바뀐 적이 있어 이 순서를 유지한다.

## 사전 등록 요약

원본은 [M6 판정 규칙 1~23](hypotheses.md#m6-판정-규칙-2026-09-30-고정-m6-결과를-보기-전)이다. 이 요약은 판정 규칙을 변경하지 않는다.

1. H5 풀은 골드 test identifier 4 + sql 4 + multi_doc 5 = 13문항이며 나머지는 기술 통계다. 보조(판정 아님)로 실버 test 83문항 답변을 같은 고정 설정으로 함께 생성하고, M7에서 identifier 15 + multi_doc 14 = 29문항의 짝 비교를 방향 확인용 기술 통계로 보고한다.
2. H5는 문항 짝 비교 부트스트랩 10,000회·시드 20260930, Agentic−단순 정답성 차이와 95% CI로 판정한다. 유형별은 기술 통계다. 보조 분석(판정 아님)으로 sql 4문항을 뺀 9문항(identifier 4 + multi_doc 5)의 차이와 95% CI도 같은 방법으로 함께 보고한다.

10. dev 골드 20 + 실버 55 = 75문항을 두 시스템·두 모델로 실행한다.
11. 정규화한 정답 값 전부 포함률, 값이 있는 같은 56문항 분모·출처별 보고·제외 ID 기록.

## 답변 모델 선택과 정답 값 포함률 지표의 한계

- 선택은 사전 등록 규칙 13대로 gpt-6-luna(`cheaper_on_tie`)로 유지한다. 게이트 (a)(b) 누설은 두 모델 모두 0건이었고, 두 시스템 평균 정답 값 포함률의 모델 간 짝 비교 차이는 0(95% CI −0.027~0.027)이라 비용이 낮은 Luna가 선택됐다.
- **이 차이 0은 동등성의 증거가 아니라 지표 해상도 부족이다.** 분모 56문항 중 43문항은 `answer_values`가 문장형(어미로 끝나는 값)이고, 정규화 부분 문자열 일치가 어미 차이만으로도 실패했다(예: dev g-syn-001의 기대 값 '…추가하기로 결정했다.'에 대해 Luna 답변은 같은 내용을 '…결정했습니다'로 써서 불일치). 네 조합(2모델 × 2시스템) 모두 이 43문항에서 0점이었다. 나머지 짧은 값 13문항 중 네 조합에서 한 번이라도 일치한 문항은 7개이고, 모델 간 일치가 달랐던 문항은 g-real-011(Sol 우세)·s-syn-069(Luna 우세) 둘뿐이라 차이가 정확히 0이 됐다.
- 같은 한계가 test의 정답 값 포함률에도 적용된다(골드 test 분모 16 중 문장형 2, 실버 test 분모 65 중 문장형 47). 결정론 지표 규칙을 M7에서 쓸 때 정답 값 형태(문장형/짧은 값)를 먼저 확인한다.
- H5는 선택한 같은 모델로 두 시스템을 비교하므로 모델 선택의 영향을 받지 않는다. 모델 선택의 적절성은 M7에서 Sol의 dev 답변도 채점해 사후 기술 통계로 확인한다.

## 관찰(기술 통계, H5 판정 아님)

**Luna(dev)**
- unanswerable 8문항에서 Agentic이 4/8을 `refused=false`로 처리했다(g-syn-023, s-syn-137, s-syn-145, s-syn-150). 4건 모두 질문이 요구한 값(비용·영향 사용자 수)이 근거에 없다고 밝히고 근거에 있는 내용을 덧붙인 부분 답변이었고, 요구된 수치를 만들어내지는 않았다(4건 직접 확인). 단순 RAG는 7/8을 거절했다. Sol은 두 시스템 모두 8/8을 거절했다.
- permission 8문항은 두 모델·두 시스템에서 전부 거절했다(dev 8/8). test에서도 골드 3/3·실버 9/9를 두 시스템 모두 거절했다.
- test g-real-014 단순 RAG는 인용 `section_key`에 메모성 긴 문장(67자)을 넣어 그 인용이 탈락하고 `no_valid_citation`으로 거절됐다. 검증기가 정상 동작한 것이며 모델의 형식 위반이다. 같은 문항에서 Agentic은 유효한 인용으로 답했다.

**test(골드 30문항, 판정 아님)**
- sql 4문항(전부 합성): Agentic은 4/4를 SQL 결과값으로 답했고, 단순 RAG는 4/4를 거절했다(`run_sql`이 없다).
- multi_doc 합성 3문항: Agentic만 답했다(3/3 대 0/3). 실제 2문항은 단순 1, Agentic 2.
- identifier(실제 1·합성 3): 두 시스템의 답변 수가 같다(각 3/4).
- 지연 P50은 단순 RAG 2.92초, Agentic 7.43초(동시성 4, 임베더 로딩 제외). P95 판정은 M7의 동시성 1 별도 실행에서 한다.
- 실버 test 83문항에서 Agentic의 `guardrail_max_steps` 종료가 5건 있었다(골드 test는 0건). 가드레일 종료는 실패로 센다(규칙 6).

**비용·지연(생성 영역 표 참조)** 골드 test 비용은 $0.047(단순 $0.014 + Agentic $0.033), 실버 test는 $0.155(단순 $0.041 + Agentic $0.114), test 합계 $0.202다. dev 지연 P50은 Luna 단순 2.93초·Agentic 8.65초, Sol 단순 5.01초·Agentic 16.05초다.

## dev 실행 비용 이력과 콘솔 대조

원장(`costs.jsonl`)의 `m6-dev` 항목은 세 번의 실행이 한 `run_id`로 합쳐져 있어 시각으로 나눴다(VAT 포함, USD).

| 실행 | 원장 비용 | 비고 |
| --- | --- | --- |
| 파일럿(20행, 무효) | 0.17 | 인용 검증 버그 구간, 선택에 쓰지 않음 |
| dev 1차(300행, 무효) | 3.09 | 인용 검증 버그(`dev 실행 이력` 표 참조), 선택에 쓰지 않음 |
| dev 2차(300행, 유효) | 1.82 | 검증기 수정 후 재실행, 모델 선택에 사용 |
| test 1회 | 0.20 | 골드 0.05 + 실버 0.15 |

- dry-run 예상은 dev 비교 $10.06(상한 $41.58)이었고 유효 2차 실제는 $1.82였다. 예상은 Agentic 도구 턴 3회·턴당 6,000자 가정이라 과대했다.
- 콘솔 대조(FP-037): Luna 파일럿은 토큰 49,644로 콘솔과 원장이 일치했다. Sol 반영분의 콘솔 대조 결과는 콘솔 확인 후 이 절에 추가한다. 그 전까지 원장은 미검증이다.

## prefer_current: 비 temporal 문항의 순서 변경

골드 temporal 5문항의 개정 전 우선은 M5의 2/5에서 0/5가 됐다(생성 영역 표). 비 temporal 문항 중 상위 10이 바뀐 것은 3문항이다: g-real-006(순서만), g-real-009·g-real-014(구성 변경). 세 문항의 정답 문서는 모두 현행판이다. 같은 규정의 여러 판이 상위에 함께 오면 temporal 문항이 아니어도 교환이 일어난다(규칙 16). 이 관찰은 M5 판정을 바꾸지 않는다.

## M7로 넘기는 결정

판정 규칙을 바꾸지 않는 처리 항목이다(hypotheses.md 변경 기록에도 남겼다).

- Gemini 채점 시 Sol의 dev 답변도 함께 채점해 모델 선택의 적절성을 사후 기술 통계로 확인한다.
- 보안 테스트셋에서 Luna의 부분 답변 경향(unanswerable 4/8을 거절하지 않고 부분 답변)이 (c) 누설(권한 밖 정답 문항에서 답 없음과 구별되는 응답)로 이어지는지 확인한다.
- 채점 호출량 추정: 골드·실버 test 113문항 × 2시스템 × 3회 + dev 300 × 3회 ≈ 1,600회. Gemini 무료 등급의 호출·일일 한도를 먼저 확인한다.
- 결정론 지표 규칙을 쓸 때 정답 값 형태(문장형/짧은 값)를 먼저 확인한다(위 정답 값 포함률의 한계).

## 한계

- 시스템·문항당 1회 실행이라 비결정성이 결과에 섞인다(temperature 미지원 모델, effort low).
- 가드레일·billing_uncertain 실패를 실패로 세는 규칙은 호출이 많은 Agentic에 불리할 수 있다.
- 골드 temporal 5문항의 정답은 모두 현행이다. prefer_current는 **날짜를 명시해 옛 판을 묻는 질문**을 처리하지 못한다.
- dev 비교 정답 값 포함률은 값이 있는 56문항만 잰다. 실제 문항은 3개뿐이라 출처별 결론은 참고용이다.
- dev 조정·비교 문항과 test는 분리되어 있으나 표본이 작아 CI가 넓다.
- MCP 인증은 데모용 정적 토큰이며 OAuth 2.1이 아니다.
- OpenAI 원장은 콘솔 청구와 첫 실행 뒤 대조 전까지 미검증이다.
- 지연은 동시성 4 실행이라 P95 판정에 쓰지 않는다.
- 정답 값 포함률은 문장형 `answer_values`에서 어미 차이만으로 0점이 되어(dev 분모 56 중 43문항, 네 조합 모두 0점) 모델·시스템 간 해상도가 낮다. dev 모델 비교의 차이 0은 동등성의 증거가 아니다.
- Luna는 근거에 없는 질문에 부분 답변을 하는 경향이 있다(dev unanswerable Agentic 4/8). 답 없음 정확도와 (c) 누설에 미치는 영향은 M7에서 본다.
- OpenAI 원장 대조는 Luna 파일럿만 일치하고 Sol 반영분은 콘솔 확인 전이다.
- `m6-dev` 원장 항목은 파일럿·1차(무효)·2차가 한 `run_id`라 시각으로 나눈 값이다.
