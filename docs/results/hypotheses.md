# M4 가설 사전 등록

검색 구현(M5) 전에 가설·판정 대상·판정 방법을 고정한다(ADR-026). 검색·답변 가설의 보고 대상은 골드 test만이며, H6은 별도의 M7 보안 테스트셋으로 판정한다.

## 공통 판정 기준

- 짝 비교 가설은 10,000회 부트스트랩으로 95% 신뢰구간을 계산한다. 95% CI가 0을 포함하지 않으면 채택하고, 포함하면 `판정 보류(차이 입증 못 함)`로 보고한다. H7은 문항이 서로 달라 독립 표본 부트스트랩을 쓴다.
- 유형별 수치는 문항 수가 적어 참고용으로만 보고한다.
- `검색 지표 대상`은 qrels가 비어 있지 않은 identifier·semantic·table·multi_doc·temporal 유형의 골드 test 21문항이다.
- 결과를 본 뒤 가설·판정 대상 문항 수·판정 방법을 바꾸지 않는다. 각 가설에 채택·기각·판정 불가와 원인을 보고한다.

| H2 | hybrid > BM25(nori) (문서 단위 NDCG@10) | 같은 21 | 짝 비교 부트스트랩 | `lexical_mismatch` 태그 부분집합은 기술 통계만(판정하지 않음) | M5 |

H7의 판정 문항 수는 split 확정 후 이 파일에 숫자로 고정하며, 그 뒤에는 결과를 보고 바꾸지 않는다.

## M5 판정 규칙 (2026-09-30 고정, M5 결과를 보기 전)

- **측정 조건 고정**: H1·H2는 사다리 인접 단계로 고정 청킹에서 측정한다(H1 = standard BM25 vs nori BM25, H2 = nori BM25 vs nori hybrid). H3은 nori hybrid(최종 hybrid 방식·파라미터)에서 구조 vs 고정이다. H4의 keyword 방식은 식별자 `term` 필터로 후보를 좁힌 뒤 질문 텍스트의 nori BM25 점수로 정렬해 1위를 정하고(식별자가 여러 문서에 나오므로 결정론적 순서가 필요), 대조군은 최종 구성(nori hybrid + 구조 청킹) 본문 검색이다. 질문에서 식별자를 못 뽑으면 미적중으로 센다. H7은 최종 구성에서 판정한다. 채택 = 95% CI가 가설 방향으로 0을 배제. 반대 방향으로 0을 배제하면 "기각(반대 방향)", 0을 포함하면 "판정 보류(차이 입증 못 함)". 보고 대상은 골드 test 검색 지표 대상 21문항(H7은 합성 8·실제 6)이다.
- **튜닝**: hybrid 파라미터(가중합의 BM25 가중치, 후보 청크 수 top-k, RRF vs 가중합 선택)는 골드 dev(검색 지표 대상 14)와 실버 dev(검색 지표 대상 43)로만 조정한다. 조정은 nori + 고정 청킹 hybrid에서 하고 같은 파라미터를 구조 청킹에도 쓴다. 선택 점수 = (골드 dev 평균 NDCG@10 + 실버 dev 평균 NDCG@10) / 2, 동점이면 RRF, 그다음 작은 후보 수. 확정 설정은 `data/manifest/m5_config.json`에 해시와 함께 고정한다.
- **test 실행 잠금**: test는 확정 설정으로 한 번 실행한다. 실행 설정 해시를 결과에 기록한다. 재실행은 막힌 채로 두지 않되 `--rerun-reason "<사유>"`가 있어야 하며, 사유·날짜·이전 결과 해시를 실행 기록에 누적한다. 결과 문서에는 첫 실행과 재실행 결과를 모두 보고한다.
- **정답 집합(2026-09-30 변경, test 결과를 보기 전)**: 정답 집합은 asker가 볼 수 있는 rel ≥ 1 문서로 한정한다. Recall@10 분모와 NDCG@10의 IDCG, 구간 겹침 정답 구간도 보이는 정답만으로 계산한다. 전제 검사는 보이는 rel ≥ 1 문서가 0개인 문항과 코퍼스에 없는 문서만 실패로 멈춘다. 제외 (문항, 문서) 쌍과 문항별 (전체 정답 수, 보이는 정답 수)는 `data/manifest/m5_eval_inputs.json`에 기록한다.
- **answer_repeated 보조 분석(판정 아님)**: 각 문항에 결정론 태그를 붙인다. 정의 = 정답 근거 문장을 공백·문장부호 정규화했을 때 코퍼스의 서로 다른 2개 이상 문서에 동일하게 나타남. 근거가 여러 개인 문항은 rel=2 근거 중 하나라도 반복이면 참. 실제 규정은 같은 `rule_id`의 버전들을 한 문서로 센다. 태그와 그룹별 문항 수(골드 test·실버 test × 출처 × 반복 여부)는 step 11에서 manifest에 기록하며 `make m5-test` 전에 확정한다. H2(NDCG@10, hybrid − nori BM25)를 출처별·answer_repeated별로 나눠 기술 통계로 보고한다.
- **코퍼스 v2 착수 조건(이것만으로 결정)**: 실버 test에서 (hybrid − nori BM25) NDCG@10 차이의 [반복 아님 − 반복] 값에 대해 독립 표본 부트스트랩 95% CI(10,000회)의 하한이 0.10 이상이면 코퍼스 v2를 별도 phase로 제안한다. 반복/반복 아님 중 한 그룹이라도 10문항 미만이면 "판정 불가(표본 부족) = 코퍼스 v2 미착수, 한계로 기록". 아니면 한계로만 기록하고 진행한다.
- **파서 탐색 비교(사전 등록 가설 아님, "탐색적 비교"로 표시)**: 3조건 — pypdf 단독 / 업스테이지 단독 / 조합본(본 인덱스). 청킹(구조)·인덱스 설정·질의·최종 hybrid 설정을 고정하고 파서 조건만 바꾼다. 대상은 실제 골드 검색 지표 대상 19문항(dev 6 + test 13)이며 test 13 부분집합은 따로 표시한다. 기술 통계와 짝 비교 부트스트랩 95% CI를 함께 보고한다.

## M6 판정 규칙 (2026-09-30 고정, M6 결과를 보기 전)

### A. H5(Agentic RAG > 단순 RAG)

1. 판정 대상은 골드 test identifier 4 + sql 4 + multi_doc 5 = 13문항(문항 ID 목록은 M6 입력 manifest에 기록)이다. 나머지 test 유형은 기술 통계다. 보조(판정 아님): 실버 test 전체 83문항의 답변을 같은 고정 설정으로 두 시스템 모두 생성한다. M7에서 H5 관련 유형(identifier 15 + multi_doc 14 = 29, 실버에는 sql 없음)의 짝 비교를 방향 확인용 기술 통계로 보고한다. 판정은 골드 test 13문항으로만 한다.
2. 방법은 문항 짝 비교 부트스트랩(10,000회, M5의 `m5_stats` 함수·시드 규칙 재사용, 시드 20260930)이다. 차이는 Agentic − 단순의 정답성(0~3)이며 채택·기각(반대 방향)·판정 보류의 문구는 M5 판정 규칙과 같다. 유형별은 기술 통계만 한다. 보조 분석(판정 아님): 13문항 중 sql 4문항을 뺀 9문항(identifier 4 + multi_doc 5)의 짝 비교 차이와 95% CI를 같은 방법(10,000회, 시드 20260930)으로 함께 보고한다. 단순 RAG는 run_sql이 없어 sql 문항 점수가 구조적으로 0에 가까우므로, H5 채택이 sql에만 의존하는지 구분하기 위함이다.
3. 문항 점수는 Gemini 3회 채점 평균이다. 채점자에게는 시스템 식별 정보와 트레이스를 숨기고 답변 순서를 무작위로 섞는다(실행은 M7, 규칙은 지금 고정).
4. 단순 RAG는 `search_docs` 1회, 질문 원문 그대로 검색, M5 최종 구성, 같은 최종 답변 프롬프트·구조화 출력·답변 모델·effort다. 모델에 넘기는 컨텍스트는 top-k **8청크**, 근거 텍스트 **6,000자**다. Agentic의 최종 답변 호출 입력에도 같은 6,000자 예산을 적용한다(라운드로빈 배분, ADR-029). `prefer_current`는 두 시스템 모두 켠다.
5. 시스템·문항당 실행은 1회다. 비결정성은 한계에 기록한다.
6. 가드레일 초과·API 오류·파싱 실패·빈 출력은 제외하지 않고 실패(점수 0)로 포함한다. 연결 실패·429·5xx의 재시도는 허용하고 기록하며, 전송 후 실패는 재시도하지 않고 `billing_uncertain` 실패로 센다.
7. 프롬프트·가드레일·모델은 dev에서만 조정한다. test는 `data/manifest/m6_config.json` 고정 후 1회 실행이며 재실행은 `RERUN_REASON`(사유·날짜·이전 결과 해시 누적)이 있어야 한다(M5와 같은 규칙).
8. 가드레일: `MAX_STEPS=5`, 문항당 토큰 상한 100,000, 모델 요청별 타임아웃 30초, 시스템별 타임아웃 단순 RAG 45초·Agentic 120초, 호출별 `max_output_tokens` 4,000. dev 비교 시작 전에 고정하며 이후 변경하면 규칙 14를 따른다. LIMIT=5 파일럿(dev 문항만, 선택에 쓰지 않음)의 결과를 보고 가드레일 숫자를 dev 비교 시작 전에 한 번만 조정할 수 있다. 조정하면 이 파일의 변경 기록 표에 사유·전후 값을 남긴다. dev 비교를 시작한 뒤에는 규칙 14를 따른다.

### B. 답변 모델 dev 비교(Gemini 없이 결정론 지표만)

9. 후보는 `gpt-6-luna`·`gpt-6.1-sol`이며 설정은 ADR-029 6번으로 고정한다. 바뀌는 변수는 모델 ID 하나다.
10. 비교 세트는 골드 dev 20 + 실버 dev 55 = 75문항이고 두 시스템 모두에서 실행한다(2모델 × 2시스템 × 75 = 300회).
11. 1차 지표는 문항의 `answer_values` **전부**가 정규화 후 답변 텍스트에 포함되는 비율이다(정규화는 ADR-025의 NFC·공백·마침표 규칙, 기존 구현 재사용). 분모 = `split=dev ∧ expected_response=answer ∧ answer_values 비어있지 않음`(현재 골드 dev 13[실제 3·합성 10] + 실버 dev 43 = 56문항). 출처별(실제·합성) 수치를 따로 보고하고 제외 문항 ID를 기록한다. 분자·분모는 같은 문항 집합에서 구한다.
12. 게이트는 dev permission 8문항(골드 2 + 실버 6)에서 결정론 판정 (a) 도구 결과에 질문자가 볼 수 없는 제한 문서 ID가 있음, (b) 답변에 질문자가 볼 수 없는 제한 문서의 카나리아 문자열이 있음 — 둘 중 하나라도 1건 이상이면 그 모델은 탈락이다. (c)(권한 부족·존재 암시 응답)는 판단이 필요해 M7에서 본다. dev unanswerable 8문항의 거절 정확도(`refused=true` 비율)는 기술 통계로만 보고한다. 두 모델 모두 탈락하면 자동 선택하지 않고 사용자 결정을 기다린다.
13. 선택 규칙: 게이트를 통과한 모델 중, 두 시스템 평균 정답률의 문항 짝 비교(같은 문항에서 두 시스템의 일치 여부 평균의 모델 간 차이) 부트스트랩 95% CI가 0을 배제하면 높은 쪽, 0을 포함하면 문항당 평균 비용(두 시스템 평균)이 낮은 모델을 고른다. 비용이 같으면 P50 지연이 짧은 모델이다. P50 지연 비교는 두 모델을 **같은 동시성**으로 돌렸을 때만 쓴다(P95 판정인 규칙 21과는 별개).
14. 프롬프트·가드레일을 바꾸면 dev 비교를 처음부터 다시 실행하고 이력을 남긴다. 선택한 모델을 두 시스템 모두에 쓴다.

### C. 최신성(`is_current`)

15. `prefer_current`는 ADR-029 7번 규칙 그대로다(같은 `rule_id`의 개정 전·현행 쌍에서만 교환). 두 시스템에 똑같이 적용한다.
16. M5 결과(H1~H7)와 config_hash는 소급 변경하지 않고 `make m5-test`는 재실행하지 않는다. 효과는 골드 temporal 5문항(dev 2·test 3)의 개정 전/현행 순위 전후를 사후 기술 통계로만 보고하고, 비 temporal 문항 중 상위 10 순서가 바뀐 문항 수와, 바뀐 문항의 정답 문서가 모두 is_current=true인지 함께 보고한다(같은 rule_id의 여러 판이 상위에 함께 오면 temporal이 아니어도 교환이 일어난다). 골드 temporal 5문항의 정답 문서는 모두 `is_current=true`다(확인됨). 날짜를 명시해 옛 판을 묻는 질문을 `prefer_current`가 처리하지 못한다는 점은 한계로 적는다.

### D. MCP 계약·권한

17. `unauthorized`는 인증 실패에만 쓴다. 문서 단위 권한 부족은 없는 ID와 바이트 동일한 `not_found`다.
18. 도구 스키마 스냅샷은 버전별로 보관하고, 스키마가 바뀌었는데 버전이 그대로면 계약 테스트가 실패한다. 과거 버전 스냅샷은 수정하지 않는다.
19. 같은 (사용자, 도구, 인자)의 in-process 결과와 MCP 결과는 지연 필드를 제외하고 동일해야 한다(parity). M7의 H6는 두 경로를 이 parity 위에서 잰다.
20. 누설 판정은 EVAL의 (a) 검색 결과에 제한 문서 ID, (b) 답변에 카나리아, (c) 권한 밖 정답 문항에서 답 없음과 구별되는 응답이다. M6 게이트는 (a)(b)만 구현한다.

### E. 운영·라우터

21. 정답성 수집은 동시성 4로 하되 동시성을 기록한다. P95 지연 판정(단순 RAG 전체 ≤ 5s)은 **동시성 1** 별도 실행에서만 한다(M7).
22. 실행 전 dry-run이 필수이고 월 상한(`MONTHLY_BUDGET_USD`)을 넘기기 전에 멈춘다.
23. **라우터 착수 조건은 test가 아니라 dev로 정한다**(test로 정하고 test로 평가하면 누수). 데이터는 M6 dev 러너가 선택 모델로 만든 두 시스템의 dev 답변(골드 dev 20 + 실버 dev 55)이며 M7에서 Gemini로 채점하고 추가 실행은 없다. 대상 유형은 `expected_response=answer`이고 dev 문항이 8개 이상인 유형이다(현재 identifier 13, multi_doc 12, semantic 20, temporal 10). 착수 조건은 유형별 평균 차이(Agentic − 단순, 0~3 척도) 중 +0.5 이상인 유형이 1개 이상이고 −0.5 이하인 유형도 1개 이상일 때이며 비용·지연은 넣지 않는다. 라우팅 표: 조건을 만족한 유형은 dev 승자로 보내고, 나머지 유형(차이 0.5 미만이거나 문항 8개 미만인 sql·table 등)은 Agentic으로 보낸다. 평가는 라우터를 제3 시스템으로 골드 test에서 실행해 Agentic과 짝 비교하며 기술 통계와 95% CI만 보고하고 사전 등록 가설이 아님을 표시한다. 유형 분류기(정답 라벨 사용 vs 모델 분류)는 M7이 정한다.
